# 한국어 지원과 관련 UI 리팩터링

## 목표

한국어와 영어를 선택할 수 있게 하고, 한국어에서도 메뉴·게임 상태·캠페인·결과·설정의 의미를 이해할 수 있도록 한다. 기존 게임 규칙과 저장된 기록은 유지한다.

## 선택한 방향

기존 Vanilla JavaScript 구조에 작은 번역 모듈을 추가한다. 외부 라이브러리나 빌드 도구는 추가하지 않는다. 한국어로만 교체하는 방식은 기존 영어 지원을 잃고, 전체 게임을 재구성하는 방식은 번역 작업보다 회귀 범위가 크므로 선택하지 않는다.

## 언어 동작

- 설정에 `한국어 / English` 선택을 추가한다.
- 저장된 언어가 있으면 우선 사용한다. 없으면 브라우저의 언어 우선순위에서 첫 지원 언어를 선택하며, 지원 언어가 없으면 영어를 사용한다.
- 언어 선택은 기존 환경설정에 저장한다. 잘못된 저장값은 안전하게 기본 언어로 복원한다.
- 선택한 언어는 새로고침 없이 현재 화면에 적용하고 문서의 `lang`도 갱신한다.
- 저장이 불가능해도 현재 세션의 언어 변경은 동작한다.

## 번역 범위

- 시작 메뉴, 모드 이름과 설명, HUD, 터치 조작, 일시정지와 조작 안내.
- 설정, 키 변경 안내, 외형 선택과 해금 알림.
- 캠페인 지도·브리핑·목표·변형 규칙·업그레이드·오류·결과.
- 게임 종료·클리어·점수 저장·리더보드·확인 대화상자.
- 접근성 이름, 입력 placeholder, 시간·등급·개인 최고 기록 관련 동적 문구.
- Neon Drop, BYTE 등 고유 이름과 SRS/DAS/ARR/20G 등 기술 표기는 유지한다. 한국어 설명에서는 홀드·하드 드롭·T-스핀 등 통용 용어를 사용한다.

## 리팩터링 범위

- 한국어·영어 문구와 매개변수 치환을 `src/js/i18n.js`로 모은다.
- 정적인 DOM 문구는 명시적인 번역 키로 적용한다. 입력된 닉네임이나 저장된 사용자 텍스트를 임의로 번역하지 않는다.
- DOM 적용·언어 변경 시 화면 갱신을 작은 UI 모듈 또는 기존 화면 함수로 정리한다. 실제 코드 의존성을 확인해 불필요한 모듈은 만들지 않는다.
- 점수·캠페인 규칙은 언어와 무관한 상태를 유지하고, 화면에 표시할 때 번역한다.
- 기존 모드 ID, 피스 ID, 저장 키와 기록 구조는 바꾸지 않는다.
- 한국어 글꼴 대체와 줄바꿈을 확인하고 필요한 CSS만 수정한다.
- 게임 루프 전체 분할, 새 프레임워크 도입, 시각 디자인 변경은 이번 범위에 포함하지 않는다.

## 검증

- 번역 키 일치·문구 치환·지원 언어 선택·잘못된 언어 설정을 유닛 테스트로 확인한다.
- 한국어 첫 실행, 언어 전환, 재실행 복원, 메뉴·설정·캠페인·게임·결과·접근성 문구를 브라우저 테스트로 확인한다.
- 기존 영어 브라우저 회귀 테스트는 언어를 명시해 환경과 무관하게 실행한다.
- 한국어 데스크톱·모바일 화면에서 주요 버튼과 설명의 잘림을 확인한다.
- 최종 `npm test`, 문법 검사, `git diff --check`를 실행하고 결과를 LLMWiki에 기록한다.

## 보존할 작업

직전 리뷰에서 수정한 설정 정규화, ARR 0 게임 루프, 0라인 B2B 점수와 관련 테스트를 유지한다. 기존 사용자 변경을 덮어쓰지 않는다.
